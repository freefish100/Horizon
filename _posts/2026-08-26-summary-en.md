## [Firefox 157 to Enable JPEG XL by Default on All Platforms](https://groups.google.com/a/mozilla.org/g/dev-platform/c/3YMV4MS34KA?pli=1) ⭐️ 8.0/10

Firefox 157 will enable JPEG XL support by default on all platforms, removing the need for users to toggle a flag. This makes Firefox one of the first major browsers to ship the format without opt-in. By enabling JPEG XL by default, Firefox significantly expands consumer access to a modern image format that beats JPEG and PNG in compression and features. It also pressures other browser vendors and the wider web ecosystem to accelerate adoption. Mozilla is adopting the Rust-based jxl-rs library, and Chromium is following the same approach. Apple has already shipped libjxl (C++) on its platforms, so the three major engine vendors are now converging on JPEG XL support.

hackernews · yboris · Aug 25, 17:55 · [Discussion](https://news.ycombinator.com/item?id=49437946)

**Background**: JPEG XL is an open, royalty-free image format developed by the JPEG committee with Google and Cloudinary, standardized as ISO/IEC 18181. It supports both lossy and lossless compression, wide color gamut, HDR, and high bit depth. Despite its advantages, browser support has been limited, and Safari shipped support in 2025 while Chrome and Firefox have been evaluating it. Firefox 157's default enablement marks a milestone in making the format a mainstream web standard.

## [EVE Online Begins Migration from Stackless Python 2.7 to Python 3](https://simonwillison.net/2026/Aug/25/eve-online-move-to-python-3/) ⭐️ 8.0/10

EVE Online announced the start of its migration from Stackless Python 2.7 to Python 3. The process will use the futurize script against 2.4 million lines of code, followed by manual review of approximately 20,000 places where Python 2 and 3 behave differently. This is a landmark project for the Python community, demonstrating how a large, legacy, 20-year-old codebase can be modernized. It also shows the practical challenges of migrating from Stackless Python, a discontinued interpreter, and could offer patterns for other long-running Python projects. The migration will start with the futurize script, then involve manual review of behavioral differences such as integer division (1/2 returns 0 in Python 2 vs 0.5 in Python 3). The announcement does not specify how Stackless will be replaced, but a prior talk described replacing it in the Carbon engine for EVE Frontier using the open-source carbonengine/scheduler library.

rss · Simon Willison · Aug 25, 22:59

**Background**: Stackless Python is a fork of Python that supports microthreads called 'tasklets' and coroutines, allowing many tasks to run in a single thread. It was used by EVE Online since its 2003 launch, but it has been officially discontinued and its repository archived in February 2025. Futurize is a tool from the python-future project that automatically converts Python 2 code to Python 3 while adding compatibility layers for Python 2.

## [Continual Learning on Open-Weight Models Achieves Frontier Performance for SovereignAI](https://www.reddit.com/r/MachineLearning/comments/1vxvzju/continual_learning_of_frontier_models_for/) ⭐️ 8.0/10

A new technical report and open-weights model, Thomson 1.0, demonstrates that frontier-level AI performance can be achieved through continual learning on readily available open-weight models, rather than requiring the massive budgets of a few heavily funded labs. The model shows competitive results on agentic, safety, legal, tax, multilingual, and Deep Research benchmarks. This directly challenges the assumption that frontier AI is exclusively the domain of a handful of well-funded players, offering a concrete path to SovereignAI — the ability of any organization to independently build, deploy, and govern its own AI. The report describes a distinctive π-shaped evaluation pattern: broad improvements across a wide range of capabilities, including ones not explicitly targeted, while almost completely eliminating the catastrophic forgetting common to narrow domain adaptation. **Background**: Continual learning is a machine learning paradigm in which a model learns new tasks incrementally without forgetting previously acquired knowledge, addressing the 'catastrophic forgetting' problem that plagues narrow fine-tuning. Frontier models are the most advanced AI models available at a given moment, and they are conventionally assumed to require enormous compute and data budgets that only a few large labs can afford. Open-weight models publicly release their trained parameters for others to use, but unlike true open-source AI, they may not include the training data. SovereignAI refers to an organization's capability to independently build, deploy, and govern AI use, and this report argues continual learning on open-weight models makes it viable for a wider range of actors.
