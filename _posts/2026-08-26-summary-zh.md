## [FDA 批准首款可连续监测酮体和血糖的可穿戴设备](https://www.fda.gov/news-events/press-announcements/fda-authorizes-first-wearable-device-continuously-monitors-both-ketone-levels-and-blood-sugar) ⭐️ 8.0/10

美国食品药品监督管理局（FDA）批准了雅培（Abbott Laboratories）的可穿戴设备，这是首款可同时连续监测酮体和血糖水平的设备。该授权于 2026 年 8 月 25 日宣布，标志着糖尿病技术的重大进步。 这一批准意义重大，因为它为糖尿病患者（尤其是 1 型糖尿病患者）提供实时酮体升高警告，降低糖尿病酮症酸中毒（DKA）风险。这也标志着健康监测设备正朝着更整合、多种生物标志物同时感测的方向发展。 该传感器是一个插入皮下的细小柔性尖端，与现有连续血糖监测仪（CGM）类似，因此虽称为“可穿戴设备”，但并非真正无创。它每分钟连续测量葡萄糖和酮体水平，在一台设备中同时提供两组数据。

hackernews · sunnynagra · 8月25日 19:07 · [社区讨论](https://news.ycombinator.com/item?id=49439017)

**背景**: 连续血糖监测仪被糖尿病患者广泛用于实时跟踪血糖，但检测酮体传统上需要单独的血液或尿液测试。酮体升高可能提示糖尿病酮症酸中毒，这是一种严重甚至致命的并发症，尤其在 1 型糖尿病中。通过将酮体感测整合进单个穿戴设备，该设备既能帮助患者避免危险的代谢危机，也能为饮食和运动决策提供参考。

## [Firefox 157 将在所有平台默认启用 JPEG XL](https://groups.google.com/a/mozilla.org/g/dev-platform/c/3YMV4MS34KA?pli=1) ⭐️ 8.0/10

Firefox 157 将在所有平台上默认启用 JPEG XL 支持，用户无需再手动开启标志。这使 Firefox 成为首批无需选择加入即可默认搭载该格式的主流浏览器之一。 通过默认启用 JPEG XL，Firefox 显著扩大了消费者对现代图像格式的使用，该格式在压缩率和功能上优于 JPEG 和 PNG。这也推动其他浏览器厂商和整个网络生态系统加速采用。 Mozilla 正在采用基于 Rust 的 jxl-rs 库，Chromium 也在走同样的路线。苹果已经在其平台上发布了 libjxl（C++），因此三大主要引擎厂商现在在 JPEG XL 支持上趋于一致。

hackernews · yboris · 8月25日 17:55 · [社区讨论](https://news.ycombinator.com/item?id=49437946)

**背景**: JPEG XL 是一种开放、免版税的图像格式，由 JPEG 委员会与 Google 和 Cloudinary 联合开发，并标准化为 ISO/IEC 18181。它同时支持有损和无损压缩、广色域、HDR 以及高比特深度。尽管具有诸多优势，但浏览器支持一度有限，Safari 于 2025 年提供了支持，而 Chrome 和 Firefox 则一直在评估中。Firefox 157 默认启用该格式标志着它向主流网络标准迈出了里程碑式的一步。

## [EVE Online 启动从 Stackless Python 2.7 到 Python 3 的迁移](https://simonwillison.net/2026/Aug/25/eve-online-move-to-python-3/) ⭐️ 8.0/10

EVE Online 宣布开始从 Stackless Python 2.7 迁移到 Python 3。迁移将使用 futurize 脚本处理 240 万行代码，随后人工审查大约 2 万个 Python 2 与 Python 3 行为差异之处。 这对 Python 社区来说是一个标志性项目，展示了如何对拥有 20 年历史的巨型遗留代码库进行现代化改造。同时，它也揭示了从已停更的 Stackless Python 迁移的实际挑战，并为其他长期运行的 Python 项目提供了可借鉴的模式。 迁移将首先使用 futurize 脚本，然后人工审查行为差异，例如整数除法（在 Python 2 中 1/2 返回 0，而在 Python 3 中返回 0.5）。公告未说明如何替代 Stackless，但此前的一场演讲介绍了使用开源 carbonengine/scheduler 库在 EVE Frontier 的 Carbon 引擎中替代 Stackless 的做法。

rss · Simon Willison · 8月25日 22:59

**背景**: Stackless Python 是 Python 的一个分支，支持称为 tasklet 的微线程和协程，允许在单个线程中运行大量任务。EVE Online 自 2003 年上线以来一直使用它，但该项目已正式停止维护，其代码仓库于 2025 年 2 月归档。futurize 是 python-future 项目中的一个工具，可自动将 Python 2 代码转换为 Python 3，并添加与 Python 2 的兼容层。

## [开放权重模型经持续学习可达前沿性能，赋能主权 AI](https://www.reddit.com/r/MachineLearning/comments/1vxvzju/continual_learning_of_frontier_models_for/) ⭐️ 8.0/10

一份新发布的技术报告和开放权重模型 Thomson 1.0 表明，通过对现成的开放权重模型进行持续学习（Continual Learning），即可达到前沿级 AI 性能，而不必依赖少数资金雄厚实验室所拥有的大规模预算。该模型在智能体任务、安全、法律、税务、多语言及深度研究（Deep Research）等广泛基准上均展现出竞争力。 这份报告直接挑战了“前沿 AI 只属于少数资金充裕机构”的固有假设，为主权 AI（SovereignAI）——即组织独立构建、部署和治理自身 AI 的能力——提供了一条具体可行的技术路径。如果该方法的结论成立，将大幅降低前沿 AI 能力的获取门槛，并可能重塑整个 AI 开发的经济格局。 报告提出了一种独特的“π形”评估结果：模型在广泛能力（包括未被明确优化的能力）上都有明显提升，同时几乎完全避免了窄领域适配中常见的灾难性遗忘问题。Thomson 采用持续学习方法，借助现代中训练与后训练（mid- & post-training）技术栈，仅对参数进行最少量的高影响干预，从而兼顾可塑性与稳定性。

reddit · r/MachineLearning · /u/Forsaken_Scientist · 8月25日 10:30

**背景**: 持续学习（Continual Learning）是一种机器学习范式，目标是让模型在不遗忘已有知识的情况下持续学习新任务，以解决窄领域微调中常见的“灾难性遗忘”问题。前沿模型（Frontier Models）指某一时刻最先进、能力最强的 AI 模型，通常被认为需要极大规模的计算、数据和资金投入，只有极少数大型实验室能够负担。开放权重模型（Open-Weight Models）会公开发布训练好的参数供他人下载和使用，但不同于真正的开源 AI，它们可能不包含训练数据。主权 AI（SovereignAI）指组织独立构建、部署和治理自身 AI 的能力；本报告主张，在开放权重模型上进行持续学习，能让更广泛的机构以远低于传统预期的预算实现这种能力。
